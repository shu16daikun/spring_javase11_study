## 0. 前提と用語

* **モジュール**

  * `main_app`（本体アプリ）
  * `my_login`（ログイン/ユーザー/権限基盤）
  * `my_util`（MyType/RoleUtil/ZeroPadding/IdBridge/ReplaceNull 等）
  * `my_exception`（MyException/MyRuntimeException/ErrorCode/ErrorUtil）
  * `my_fragment`（共通フロント資産 `/psfm`）
* **依存方針（Spring / JPMS 無効運用）**

  * `module-info.java` は作成しない（**JPMS無効**）。クラスパス型 Spring Boot 前提。
  * モジュール間依存は **Maven の pom**（jar 依存）で管理。**公開契約は api/* のみ**参照可。
  * 依存解決は **コンポーネントスキャン**（`@SpringBootApplication(scanBasePackages=...)`）。必要に応じて `@EntityScan` / `@EnableJpaRepositories`。
  * JVM の `--add-opens` は不要（反射は Spring 標準に委譲）。
* **責務の主軸**

  * Controller：薄く（I/O と遷移決定のみ）
  * Service：ユースケース・取引境界（`@Transactional`）・メソッド認可（`@PreAuthorize`）
  * Repository：各コンポーネント内に閉じる（**他モジュールの Entity/Repo 直参照禁止**／**Service API 越し**）
* **DTO 方針**

  * ViewDto：`fromEntity()` のみ（出力整形/擬似ID化）。**入力に使わない**
  * Form：`toInputDto()` / `fromViewDto()`（**Controller のみ使用可**）
  * InputDto：Service 内で `toEntity()`（private）。認可/暗号化/関連解決もここで最終確定

## 4. DTO / Form と変換ルート

**同一モジュールの画面**

* GET 初期表示：`My〈コンポ名〉Service` → `My〈...〉ViewDto` → `Form.fromViewDto(v)`
* POST 送信：`Form.toInputDto()`（＝ internal の 〈コンポ名〉InputDto）→ `ServiceImpl` → `private toEntity()`

**越境（外部モジュール→提供側）**

* 呼び手 Ctrl：Form → **api/dto** の `My〈コンポ名〉〈UseCase〉InputDto`
* 呼び出し：**api/service** の `My〈コンポ名〉Service`（引数：上記 InputDto）
* 受け手側：`ServiceImpl` → `To〈コンポ名〉EntityMapper.fromInputDto(...)` → 保存
* 返却：`To〈コンポ名〉ViewDtoMapper.fromEntity(...)` → `My〈...〉ViewDto`

## 11. DB / ID / シード方針（確定・2025-10-16 更新）

* **主キー**：接頭辞＋0埋め連番（例：`US0001`/`AU0001`/`SA00001`/`CH00000001`/`KQ00000001`/`AR00000001`/`WE00000001`/`SC001`）。**SEQ + DEFAULT** で DB 自動採番。
* **接頭辞と桁**

  * Users：`US`＋4桁
  * Authority：`AU`＋4桁
  * SankouBooks：`SA`＋5桁
  * Chapter：`CH`＋8桁
  * KurohonQuestions：`KQ`＋8桁
  * AnswerRecords：`AR`＋8桁
  * Weakness：`WE`＋8桁
  * SankouBookColor：`SC`＋**3桁**（最終確定）
* **一意制約（UNIQUE）**

  * `authority.name`／`sankou_book_color.name`／`sankou_books.name`
  * `chapter(sankou_book_id, no)`
  * `kurohon_questions(chapter_id, sankou_book_id, question_no)`
  * `answer_records(user_id, sankou_book_id, chapter_id, attempt_no, kurohon_question_id)`
* **インデックス（抜粋）**

  * `chapter(sankou_book_id, no)`
  * `kurohon_questions(chapter_id, question_no)`／`(sankou_book_id)`
  * `answer_records(user_id, sankou_book_id, chapter_id, attempt_no)`／`(kurohon_question_id)`
  * `weakness(user_id, wrong_count DESC, correct_rate)`／`(sankou_book_id, chapter_id)`
* **トリガ**

  * `answer_records.attempt_no` を **ユーザー×書籍×章** スコープで自動採番（`advisory_xact_lock` で直列化）
  * `weakness` は **answer_records INSERT をトリガに UPSERT**（累積と直近を同期／正答率は生成列）
* **テーブル追加**

  * `attempt_session`（`AS`＋10 桁採番、`answer_records.attempt_session_id` で任意紐付け。索引あり）
* **DDL 方針（再作成用“綺麗な形”）**

  * `ALTER`/`DO` は原則なし。**`CREATE TABLE` 内に DEFAULT / UNIQUE / FK を内製**。
  * 依存順に `CREATE SEQUENCE` → 参照元→参照先で `CREATE TABLE`。
  * シードは `resources/sql/schema/*.sql` → `resources/sql/data/*.sql` の順。

## 14. Getter / Setter 規約（Java 21 / Spring MVC / Thymeleaf）

> 方針: **フォーム以外は不変**。外部入力は Form に限定。AOP 対象の実装クラスは **public 非final** を維持。

### 0) 共通原則

* 公開 Setter は最小限（外部入力は **Form のみ**）
* **不変（immutable）を基本**：`ViewDto` と `InputDto` は **record** を第一候補
* Entity は **ドメイン操作メソッド**で状態変更（`public setXxx` 原則禁止）。JPA のため **デフォルトコンストラクタ（PROTECTED）** 必須
* 層の責務：

  * **Form**：Web バインディング用。`public` getter/setter 必須
  * **InputDto**：ユースケース入力。**record** 推奨（不変）
  * **ViewDto**：画面表示専用。**record** 推奨（不変）
  * **Entity**：永続化対象。Setter は `protected/package-private`。変更は意味のあるメソッド経由

### 1) Entity（JPA）

* フィールド: `private`／`@Getter`（公開）
* Setter: 原則なし。やむを得ない場合は `@Setter(AccessLevel.PROTECTED)` または `protected/package-private`
* コンストラクタ: `@NoArgsConstructor(access = AccessLevel.PROTECTED)`（JPA）＋ 業務用 `public` コンストラクタ/ファクトリ
* 変更は **意図のあるメソッド** で（例: `changePassword(...)`）
* `@EqualsAndHashCode`: ID ベースにする場合は `onlyExplicitlyIncluded=true` で `id` のみ

### 2) ViewDto（不変）

* 形式: **record**（例: `public record PasswordSetViewDto(String username) { }`）
* 付加ロジックが必要なら `static fromEntity(...)` を定義

### 3) InputDto（不変）

* 形式: **record**（例: `public record PasswordSetInputDto(String password, String passwordCheck) { }`）
* Bean Validation はレコードコンポーネントに付与可能

### 4) Form（Web バインド：可変）

* フィールド: `private`（**final 禁止**）
* Getter/Setter: **public**
* デフォルトコンストラクタ: **必須** (`@NoArgsConstructor`)
* バリデーション: `@NotBlank` 等 or カスタム `Validator`

### 5) 追加ルール

* **`@Data` は禁止**（特に Entity）
* 機密情報の Getter には必要に応じて `@JsonIgnore`
* 命名: `XxxForm` / `XxxInputDto` / `XxxViewDto`
* MapStruct は **コンストラクタ/record マッピング** を基本に（Setter 不要）

### 6) チートシート

* **Entity**: `@Getter`、`@NoArgsConstructor(PROTECTED)`、Setter 無し（必要時 PROTECTED）／変更はメソッド
* **ViewDto**: **record**（不変）
* **InputDto**: **record**（不変）
* **Form**: `@Getter @Setter @NoArgsConstructor`／`final` 禁止

> 備考: AOP 対象（`@Service/@Repository/@Component`）の実装クラスは **public 非final**

## 15. ID / DTO バリデーション規約（2025-10-18 追加）

### 1) ViewId の検証方針

* ViewId のフォーマットが未確定／共有不能な間は、api/dto 側で `@Pattern` は付けない
* 代わりに **Service 入口で `IdBridge.toEntityId(viewId)` を必ず通す**
* 不正形式は **Bridge 層で例外化**し、`@ControllerAdvice` で画面エラーへマッピング

### 2) フォーマット確定後の厳格化

* 接頭辞・桁数が確定したら、regex を定数化（`IdConstants/IdRegex` 等）

  ```java
  public final class IdRegex { public static final String KQ_VIEW = "^KQ\\d{8}$"; }
  ```
* `api/dto` の該当フィールドに `@Pattern(regexp = IdRegex.KQ_VIEW)` を付与して**早期バリデーション**
* それでも最終責務は **IdBridge** 側に残し、**二重防御**

### 3) DTO の役割

* DTO は **record（不変）**。Bean Validation は **存在・長さなどの軽量検証**
* `null`/空文字の正規化は **record のコンパクトコンストラクタ**
* 認可（`@PreAuthorize`）は DTO に付けない（Controller/Service に集約）

### 4) IdBridge の責務

* **ViewId ↔ EntityId の変換・検証を一元化**（ZeroPadding／接頭辞／桁数チェック）
* 変換失敗時は **`XxxException` + `XxxErrorCode`** を投げ、画面/API で統一ハンドリング

### 5) 実装メモ

* 既知の形式（KQ/SA/CH 等）が doc で確定済みなら `@Pattern` を積極適用
* 未確定なら `@NotBlank` のみに留め、**Bridge 検証に一本化**

## 16. 多重防衛（Validation / Authorization / Consistency）規約（2025-10-18 追加）

### 0) Frontend（validation.js / controller.js）

* 必須/長さ/簡易正規表現など **即時 UX の軽量検証のみ**
* `regex`・最小/最大は **util_module の定数** を参照（ビルド生成 or 配信）

### 1) Controller 層（Form/BindingResult）

* `@Valid` + カスタム Validator で **画面入力の妥当性を確定**（クロスフィールドも含む）
* エラー時は **テンプレ返し**（422 相当）。`BindingResult` + `errorMessage` で表示
* **Form→InputDto 変換のみ**。`IdBridge`/認可は呼び先（Service）

### 2) Service 層（ユースケース境界：最終防衛）

* `IdBridge.toEntityId(...)` を **必ず通す**
* `@PreAuthorize` による **認可の最終責務**
* **ドメイン整合**（状態遷移/上限/重複/外部キー存在）を再検証
* 違反時は `XxxException + XxxErrorCode` を送出し、Advice で一般エラーへ統一
* 冪等性/重複送信対策（トークン/バージョン）

### 3) DB（最後の柵）

* `NOT NULL` / `CHECK` / `UNIQUE` / `FK` を必ず設計
* DB 違反は Advice で **400/409** に畳む

### 4) バイパス時

* **ユーザミス**：Controller Validator → 422/同画面。ログ: `INFO`
* **改ざん/不正疑い**：Service/IdBridge/整合 → 400/一般エラー。ログ: `WARN`（`userId, route, viewId, reason`）
* 必要に応じ **進行中セッション（attempt 等）を安全に破棄/再生成**

### 5) エラーメッセージ運搬

* フィールドエラー：`BindingResult`
* 一般エラー：`PropKey.ERROR_MESSAGE`（flash or model）
* 定義キーは `error.xxx`。`ValidationMessageUtil` で文言解決

### 6) 共有定数/バージョン

* `IdRegex` / `PasswordPolicy` は **util_module に集約**。JS へは生成物で配布
* `VALIDATION_SCHEMA_VERSION` を JS/サーバ双方に保持。不一致時は **フロント検証を抑制**

## 17. エラー設計・実装（認証前/後分離＋traceId 短期保存｜2025-10-19 追加)

* 目的：例外ハンドリングを一元化し、再読込でもメッセージが消えないよう **traceId を URL に載せて短期保持**
* 命名/配置（my_exception｜ルート pkg は com.*）：

  * 画面 DTO：`com.exception.api.ErrorViewDto`（record）
  * 状態 IF：`com.exception.api.ErrorStateService`
  * 実装：`com.exception.internal.ErrorStateServiceImpl`（@Service｜TTL）
  * CSV 出力：`ErrorReportService`（my_util の `MyCsvExporter`）
* AppPath（全て `private final String`）：

  * `LOGIN_ERROR = "/login/error"`, `R_LOGIN_ERROR = "redirect:/login/error"`
  * `USER_ERROR  = "/user/error"`,  `R_USER_ERROR  = "redirect:/user/error"`
  * `ADMIN_USER  = "/admin/user"`,  `R_ADMIN_USER  = "redirect:/admin/user"`
* ハンドリング（`MyRuntimeException`）：

  1. `traceId = UUID` 発行 → `logger.error("[{}] {} {}", traceId, errorCode, ex.getMessage(), ex)`
  2. Flash：`status/errorCode/errorMessage/traceId` ＋ Redirect に `traceId` をクエリ付与
  3. `ErrorStateService.put(traceId, new ErrorViewDto(...))` 短期保持
  4. リダイレクト：未認証→`R_LOGIN_ERROR`／認証後→**権限分岐**（`ROLE_ADMIN`→`R_ADMIN_USER`／その他→`R_USER_ERROR`）
* 表示：`/login/error`（permitAll, CSV 無）／`/user/error`（認証必須, CSV 保存ボタンあり）／`/admin/user` は既存管理 UI で受けて表示
* Security：`/login`, `/login/error`, `/css/**`, `/js/**`, `/img/**`, `/psfm/**` は permitAll ／ `/admin/**` は `ROLE_ADMIN`

## 18. キャッシュ＆セッション運用（2025-10-18 追加）

* SSOT：**userId 不変／username 可変**。`Principal` に userId を必ず含める
* 自分のユーザー名変更：ログイン維持 → **SecurityContext の principal を即差し替え** → `UserCache` 等の **旧 username を evict**
* 自分のパスワードリセット：**必ずログアウト**（セッション破棄＋必要なら Remember-Me 無効）
* 管理者が他人を変更：**旧 username を evict** のみ。セッションは維持（反映は次回ログイン）
* アプリ `@Cacheable`：username キーは変更直後に evict／ID キーは原則不要。JPA は **コミット後に再取得**
* 表示：画面は「userId 固定 + username 可変」。`Authentication#getName()` 直参照は避けるか principal 差し替え後に使用

## 32. コーディング規約（最終）

### 32.1 Java（数値基準）

* 1 行最大 100 文字／1 ファイル 1,000 行目安（超過時は分割検討）
* 1 メソッド 80 行上限（目安 40）／条件ネスト深さ 2 まで（3 段目はガード節）
* 循環的複雑度：10 以下／`@Override` 必須
* マジック値禁止（0/1/-1/""/empty のみ例外）
* `static` は純関数のみ（状態保持禁止）
* `Serializable` は必要時のみ。`serialVersionUID` 明示
* コメント：**Javadoc 必須**（要約/@param/@return/@throws）。**意図**を書く
* **コメント雛形は §31.6 の Code Templates を使用**

### 32.2 Repository 方針（実装クラス排除）

* `JpaRepository` + `JpaSpecificationExecutor` を既定
* クエリは導出メソッドを基本。SQL/JPQL 直書きは最小限
* 付加ロジックは Repository インターフェースの `default` メソッドでラップ
* DB デフォルト値活用：

  * Entity に `@DynamicInsert`（null 列を INSERT から除外）
  * デフォルト列は `insertable=false, updatable=false` で DB に委任
  * `@Generated(GenerationTime.INSERT)` or save 後に `refresh/find` で読み戻す
* `messageSource` は i18n 専用。SQL/ロジックは格納しない

### 32.3 非同期/排他

* 既定は同期。必要時のみ `@Async` + 専用 Executor
* 一意/FK 制約で整合確保。必要に応じ `advisory_xact_lock` を使用

### 32.4 フロント/プロパティ

* UTF-8 固定、出力はエスケープ（`th:text` 既定、`th:utext` 禁止）
* JS は JSDoc 必須。DOM 契約（必須 class / data-属性）を先頭に明記
* properties は UTF-8。Key は `label.` / `error.` / `regex.` / `app.` / `security.`
* `PropKey` は final クラスで集中管理（window への一括積みもこちら経由）

### 32.5 Eclipse 運用

* **Code Templates（§31.6）をインポート**して Javadoc/コメントを自動生成
* Save Actions：Format / Organize imports / Add missing `@Override` を ON

## 33. テスト設計（JUnit）｜2025-10-23 追加

* レイヤ：**Unit**（Spring 起動なし）／**Slice**（`@WebMvcTest`/`@DataJpaTest`）／**Integration**（`@SpringBootTest`）
* 配置：本体と同一パッケージにミラー配置。`@SpringBootTest` はルート配下 or `classes=<エントリ>` 明示
* 命名：`XxxTest`、**1 テスト=1 責務**。メソッド名は日本語 OK
* タグ：契約系 `@Tag("contract")`、統合 `@Tag("integration")`（`-Djunit.jupiter.tags.include` で選択実行）
* 資源：`src/test/resources` 推奨。UTF-8 明示
* DB 契約：`*DB.TABLE` / `*Column` と実 DB（public）を突合。不存在/不足で失敗
* 再現性：`Clock`/`Random` は注入 or 固定。`spring.jpa.open-in-view=false`
* Mockito/JDK21 警告：`mockito-junit-jupiter`/`mockito-inline`＋ surefire `-XX:+EnableDynamicAgentLoading`
* CI：`main` は全緑。やむなしの赤は一時ホワイトリストで明示除外→後で撤去
