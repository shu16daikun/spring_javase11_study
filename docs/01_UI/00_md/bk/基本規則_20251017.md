## 0. 前提と用語

* **モジュール**
  * `main_app`（本体アプリ）
  * `spring_login_module`（ログイン/ユーザー/権限基盤）
  * `util_module`（MyType/RoleUtil/ZeroPadding/IdBridge/ReplaceNull 等）
  * `spring_exception_module`（MyException/MyRuntimeException/ErrorCode/ErrorUtil）
  * `spring_fragment_module`（共通フロント資産 `/psfm`）
* **依存方針（Spring / JPMS 無効運用）**
  * `module-info.java` は作成しない（**JPMS無効**）。クラスパス型 Spring Boot 前提。
  * モジュール間依存は **Mavenのpom**（jar依存）で管理。**公開契約は api/* のみ**参照可。
  * 依存解決は **コンポーネントスキャン**（`@SpringBootApplication(scanBasePackages=...)`）。必要に応じて `@EntityScan` / `@EnableJpaRepositories` で境界指定。
  * JVM の `--add-opens` は不要（反射は Spring 標準に委譲）。
* **責務の主軸**
  * Controller：薄く（I/O と遷移決定のみ）
  * Service：ユースケース・取引境界（`@Transactional`）・メソッド認可（`@PreAuthorize`）
  * Repository：各コンポーネント内に閉じる（**他モジュールの Entity/Repo 直参照禁止**／**Service API 越し**）
* **DTO 方針**
  * ViewDto：`fromEntity()` のみ（出力整形/擬似ID化）。**入力に使わない**
  * Form：`toInputDto()` / `fromViewDto()`（**Controllerのみ使用可**）
  * InputDto：Service内で `toEntity()`（private）。認可/暗号化/関連解決もここで最終確定

> 参考：`@Transactional` / `@Cacheable` / `@Async` / `@Validated` 等や他アドバイザでプロキシ化。

## 3. グローバル規約（実装ルール）

* インデント：**タブ**
* 文字列：**`private final String` 定数化**（Enumで崩れる箇所も文字列定数）
* 条件：**MyType** を使用。否定は **private `isNotXxx()`**（`!=`直書き禁止）
* 変数：**基本 `final`**
* 例外：`XxxException extends MyRuntimeException` + `XxxErrorCode implements ErrorCode`
* 画面向けエラー：**ControllerAdvice + ErrorUtil**（`errorCode`/`errorMessage` をflash）
* ルーティング/テンプレ：**AppPath/TempPath** 集中管理（定数のみ参照）
* **AOP対象実装**：**public 非final**（finalクラス禁止）

## 4. DTO / Form と変換ルート

**同一モジュールの画面**  
- GET：`My〈コンポ名〉Service` → `My〈…〉ViewDto` → `Form.fromViewDto(v)`  
- POST：`Form.toInputDto()`（＝internalの〈コンポ名〉InputDto）→ `ServiceImpl` → `private toEntity()`

**越境（外部モジュール→提供側）**  
- 呼び手Ctrl：Form → **api/dto** の `My〈コンポ名〉〈UseCase〉InputDto`  
- 呼び出し：**api/service** の `My〈コンポ名〉Service`（引数：上記InputDto）  
- 受け手側：`ServiceImpl` → `To〈コンポ名〉EntityMapper.fromInputDto(...)` → 保存  
- 返却：`To〈コンポ名〉ViewDtoMapper.fromEntity(...)` → `My〈…〉ViewDto`

## 11. DB / ID / シード方針（確定・2025-10-16更新）
- **主キー**：接頭辞＋0埋め連番（例：`US0001`/`AU0001`/`SA00001`/`CH00000001`/`KQ00000001`/`AR00000001`/`WE00000001`/`SC001`）。**SEQ + DEFAULT** でDB自動採番。
- **接頭辞と桁**：Users=US4／Authority=AU4／SankouBooks=SA5／Chapter=CH8／KurohonQuestions=KQ8／AnswerRecords=AR8／Weakness=WE8／SankouBookColor=SC**3**  
- **UNIQUE**：`authority.name`／`sankou_book_color.name`／`sankou_books.name`／`(sankou_book_id,no)`／`(chapter_id,sankou_book_id,question_no)`／`(user_id,sankou_book_id,chapter_id,attempt_no,kurohon_question_id)`  
- **IDX（抜粋）**：`chapter(sankou_book_id,no)`／`kurohon_questions(chapter_id,question_no)`／`answer_records(user_id,sankou_book_id,chapter_id,attempt_no)`／`weakness(user_id, wrong_count DESC, correct_rate)`  
- **トリガ**：`answer_records.attempt_no` をユーザー×書籍×章で自動採番（`advisory_xact_lock`）／`weakness`はINSERTトリガでUPSERT（生成列で正答率）  
- **テーブル**：`attempt_session`（`AS`＋10桁、`answer_records.attempt_session_id`で任意紐付け・索引あり）  
- **DDL方針**：`ALTER`/`DO`なし。`CREATE TABLE` 内に DEFAULT/UNIQUE/FK を内製。順序は SEQUENCE → 参照元 → 参照先。シードは `resources/sql/schema/*.sql` → `resources/sql/data/*.sql`

## 14. 擬似ID(ViewId) の秘密鍵運用

### 1) 秘密鍵の読取順序（ViewIdUtil）

* **環境変数** `APP_PSEUDO_ID_SECRET`
* **JVMシステムプロパティ** `app.pseudoId.secret`

> 上記が共に未設定の場合、`IllegalStateException: 擬似ID用の秘密鍵が未設定です` を送出し、500 になります。
> **`application.yml` は読みません。**

### 2) 鍵の要件

* ランダムで十分な長さ（目安: **32バイトをBase64**など）。
* `sign10` は **文字列をそのままUTF-8バイト列**として HMAC に使います。**Base64デコードは不要**。

### 3) 設定パターン（どれか1つでOK）

**A. 環境変数で渡す**

```bash
# macOS / Linux
export APP_PSEUDO_ID_SECRET="$(openssl rand -base64 32)"
```

```powershell
# Windows PowerShell
$env:APP_PSEUDO_ID_SECRET = [Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }))
```

* IntelliJ / Eclipse: Run/Debug 設定の **Environment variables** に `APP_PSEUDO_ID_SECRET=...` を追加。

**B. JVMシステムプロパティで渡す**

```bash
# java -jar
java -Dapp.pseudoId.secret=<鍵> -jar target/app.jar
```

```bash
# Maven
mvn spring-boot:run \
  -Dspring-boot.run.jvmArguments="-Dapp.pseudoId.secret=<鍵>"
```

```bash
# Gradle（必要なら）
./gradlew bootRun -Dapp.pseudoId.secret=<鍵>
```

### 4) 運用方針

* **本番:** 環境変数で注入（Secret Manager 等で管理）。
* **ローカル:** Run/Debug の環境変数 or `-Dapp.pseudoId.secret=...`。
* **禁止:** 鍵を Git にコミット／ログ出力。
* **推奨:** ローテーション・最小権限・環境毎に値を分離。

### 5) テストでの渡し方（例）

```java
// 例: @BeforeAll で JVM プロパティを注入
@BeforeAll
static void setUp() {
  System.setProperty("app.pseudoId.secret", "test-secret-32bytes-base64-like");
}

@AfterAll
static void tearDown() {
  System.clearProperty("app.pseudoId.secret");
}
```

* Spring Test を使う場合は `@DynamicPropertySource` で同等に注入可。

### 6) トラブルシュート

* 500 + Whitelabel かつ `擬似ID用の秘密鍵が未設定です` → 上記 1) のいずれかを設定して再起動。
* コンテナ環境: `docker run -e APP_PSEUDO_ID_SECRET=...`、Kubernetes: `env`/Secret マウントで注入。

## ViewId / EntityId 仕様メモ

* 形式: **`p<digits>-<sig10>`**

  * `<digits>`: EntityId 末尾の連続数字。
  * `<sig10>`: `HMAC-SHA256` → `Base64URL(=,改行なし)` → **先頭10文字**。
* `toEntityIdCandidate(viewId, prefix, totalLength)`:

  * `prefix` と `totalLength` を受けて、数字部を **ゼロ埋め** 復元。
  * 例: Users の場合 `prefix=US`, `totalLength=6` → `US0001` など。

## Spring Data JPA リポジトリ規約（@Modifying）

> ログイン時の例外:
> `Modifying queries can only use void or int/Integer as return type; Offending method: Optional ... AuthorityRepository.getNameById(String)`

### 原則

* **SELECT クエリには `@Modifying` を付けない。**
* `@Modifying` を付けるメソッドの戻り値は **`void` または `int/Integer`**。

### 正しい例

**SELECT の場合**

```java
public interface AuthorityRepository extends JpaRepository<Authority, String> {
  @Query("select a.name from Authority a where a.id = :id")
  Optional<String> getNameById(@Param("id") String id);
}
```

**更新系の例**

```java
@Modifying
@Query("update Authority a set a.name = :name where a.id = :id")
int updateNameById(@Param("id") String id, @Param("name") String name);
```

### ありがちなNG

* `@Modifying` が付いたまま **`Optional<...>` を戻す**。
* UPDATE/DELETE クエリで **`int` を返していない**。

## `application.yml` で管理したい場合

現実装（`ViewIdUtil.loadSecret()`）は `System.getenv` / `System.getProperty` のみ参照。`application.yml` は見ません。

### 方針A: 実装をSpring設定に寄せる

```java
@Component
public class ViewIdSecretProvider {
  @Value("${app.pseudoId.secret}")
  private String secret;
  public String get() { return secret; }
}
```

* `ViewIdUtil` が `static` ユーティリティの場合は、起動時（`@PostConstruct` など）に一度だけ `ViewIdUtil#setSecret(...)` のような形で注入する設計に変更する。

### 方針B: 運用で吸収する

* `application.yml` に値は置かず、**環境変数 or JVM プロパティ**に流す運用を徹底。
