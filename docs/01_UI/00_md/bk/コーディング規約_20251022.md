# コーディング規約.md
（Java資格勉強_黒本学習システム開発 / 2025-10-22）

## 1. 総則

### 1.1 目的  
安全で保守しやすいシステムを実現するため、言語ごとの書式と記述ルールを統一する。  
目的は以下の3点：  
- 読みやすく、追えるコードを残すこと  
- DB・サーバ・ブラウザ間の責務を明確にすること  
- 意図の分かるコメントで自走可能にすること  

### 1.2 適用範囲  
全モジュール（Java / JS / CSS / HTML / SQL / properties）に適用。  
**インデントは全言語タブ統一**とする（例外はYAMLのみ2スペース）。

## 2. Java実装規約

### 2.1 構造・行数・ネスト

| 項目 | 規定値 | 備考 |
|------|--------|------|
| 1行最大文字数 | 100文字 | 改行優先（引数は1引数/行で折返し） |
| ファイル行数 | 1,000行目安 | 超過時は分割を検討 |
| メソッド行数 | 80行上限（40目安） | 小分割・早期return |
| ネスト深さ | 2段まで | 3段目はガード節で脱出 |
| 循環的複雑度 | 10以下 | 超過時はメソッド分割 |

---

### 2.2 記法／命名ルール

| 要素 | 規約 |
|------|------|
| インデント | タブ固定（4幅） |
| 条件判定 | `MyType` を使用。否定は `isNotXxx()` |
| 定数 | `private static final String` 形式。マジック値禁止（0/1/-1/""/emptyのみ例外） |
| DTO | `record`（Java21）で定義。Formのみ可変 |
| コメント | 「なぜそう書くか」を記述（手順説明は不要） |
| Javadoc | public/protected メソッド必須（`@param` / `@return` / `@throws`） |
| アクセス修飾子順序 | public → protected → package-private → private → abstract → static → final |
| @Override | 必須 |
| static利用 | **純関数のみ許可**。状態保持は禁止 |
| Serializable | 必要時のみ。`serialVersionUID` を明示 |
| import | ワイルドカード禁止（明示import） |

### 2.3 EntityとDBデフォルト値（A方針）

#### 設定例
```java
@Entity
@DynamicInsert // null列をINSERT文に含めない
@Table(name = "users")
final class UsersEntity {
	@Id
	@Column(name = "id")
	private String id;

	@Column(
		name = "created_at",
		insertable = false,
		updatable = false,
		columnDefinition = "timestamp with time zone default now()"
	)
	@Generated(GenerationTime.INSERT)
	private OffsetDateTime createdAt;
}
```

#### ルール
| 目的 | 設定 | 補足 |
|------|------|------|
| DBデフォルト尊重 | `@DynamicInsert` | Hibernate専用だが採用可 |
| DBが埋める列 | `insertable=false, updatable=false` | |
| DB値即反映 | `@Generated(GenerationTime.INSERT)` or `save→refresh()` | |
| 更新日時等 | `@PreUpdate` or DBトリガー | |

### 2.4 Repository方針（実装クラス排除）

#### 構成原則
- Repositoryは **インターフェースのみ**。Implを作らない。  
- CRUDはJpaRepository、条件検索はJpaSpecificationExecutor。  
- 付加処理はdefaultメソッド内で実装可。
- SQLの使用はJPQLのみ記述可。

```java
public interface AttemptSessionRepository
		extends JpaRepository<AttemptSessionEntity, String>,
		        JpaSpecificationExecutor<AttemptSessionEntity> {

	Optional<AttemptSessionEntity> findTopByUserIdOrderByCreatedAtDesc(String userId);

	default AttemptSessionEntity saveAndReload(AttemptSessionEntity e, EntityManager em) {
		AttemptSessionEntity saved = save(e);
		em.refresh(saved);
		return saved;
	}
}
```

---

### 2.5 Specification共通例
```java
public final class AttemptSessionSpecs {
	private AttemptSessionSpecs() {}
	public static Specification<AttemptSessionEntity> userIdEquals(String userId) {
		return (root, q, cb) -> cb.equal(root.get("userId"), userId);
	}
}
```

---

### 2.6 例外・エラーコード
- 例外は `MyRuntimeException` 派生クラスで統一。  
- エラーコードは `ErrorCode` 実装enumで管理。  
- 画面出力は `userCode`（問い合わせ番号）までに限定。内部構造は出さない。

## 3. フロントエンド規約

### 3.1 HTML/Thymeleaf
- `<meta charset="UTF-8">` 必須。  
- 出力は `th:text`（エスケープ）を原則。`th:utext`は禁止。  
- セクション区切りコメントを明示：  
	```html
	<!-- [header] START -->
	<!-- [header] END -->
	```

### 3.2 JavaScript
| 項目 | 内容 |
|------|------|
| インデント | タブ固定（4幅） |
| コメント | JSDoc準拠（目的 / 引数 / 戻り値） |
| DOM契約 | 必須class・data属性を冒頭に明記 |
| ファイル命名 | キャメル／ケバブ（例：`setAlertDanger.js`） |
| XSS防止 | `textContent` / `innerText`使用。`innerHTML`禁止。 |
| 共通処理 | `/psfm/js/fragment/` 配下に集約。 |

### 3.3 CSS
- UTF-8。  
- インデント：タブ。  
- カラー／サイズはCSS変数で統一管理。  
- ユーティリティは `my-` プレフィックス採用。

## 4. properties / messages

| 要素 | 規約 |
|------|------|
| エンコーディング | UTF-8（native2ascii禁止） |
| コメント | キー群単位で1行説明 |
| Key命名 | `label.` / `error.` / `regex.` / `app.` / `security.` |
| PropKey | finalクラスで集中管理（`window`への一括展開もここ経由） |
| messageSource | 国際化専用（SQL・ロジックは格納禁止） |

---

## 5. 非同期・排他制御

| 項目 | 規約 |
|------|------|
| 非同期処理 | 必要時のみ `@Async` + 専用`TaskExecutor` |
| 進捗確認 | ポーリング or 軽量WebSocket（将来対応） |
| 排他制御 | DB整合 + 一意制約 + `advisory_xact_lock` |
| ステート共有 | 禁止（コンテナ管理Beanはステートレス） |

## 6. Eclipse / Prettier / EditorConfig運用

### 6.1 共通ルール
- **全言語タブインデント統一（4幅）**。  
- 保存時自動整形で強制適用。  
- YAMLのみ慣例上2スペース許可。
