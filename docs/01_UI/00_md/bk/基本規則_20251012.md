## 0. 前提と用語
- **モジュール**
	- `main_app`（本体アプリ）
	- `spring_login_module`（ログイン/ユーザー/権限基盤）
	- `util_module`（MyType/RoleUtil/ZeroPadding/IdBridge/ReplaceNull 等）
	- `spring_exception_module`（MyException/MyRuntimeException/ErrorCode/ErrorUtil）
	- `spring_fragment_module`（共通フロント資産 `/psfm`）
- **依存方針**
	- 継承は**最小限**、モジュール間は**利用（合成）**で接続
	- 他モジュールの **Entity / Repository 直参照禁止**（**Service API 越し**）
- **責務の主軸**
	- Controller：薄く（I/O と遷移決定のみ）
	- Service：ユースケース・取引境界（`@Transactional`）・メソッド認可（`@PreAuthorize`）
	- Repository：各コンポーネント内に閉じる
- **DTO 方針**
	- ViewDto：`fromEntity()` のみ（出力整形/擬似ID化）。**入力に使わない**
	- Form：`toInputDto()` / `fromViewDto()`。**Controllerのみ使用可能。ServiceへはInputDtoに変換して受け渡し**
	- InputDto：**Service 内**で `toEntity()`（private）し、認可/暗号化/関連解決
- **正規化/ルール**
	- ID 桁：`ZeroPadding`、擬似/実ID：`IdBridge`、ロール表現：`RoleUtil`
	- null/空/比較：`MyType`・`ReplaceNull`
	- パス/テンプレ：`AppPath`・`TempPath`
	- 文言/I18N：`ValidationMessageUtil`
	- フロント条件判定：`/psfm/js/common/utils.js`

## 1. モジュール依存（→ は「利用」）
- `main_app` → `spring_login_module`（Users/Authority/PasswordSet **Service API**）
- `main_app` → `spring_exception_module`（例外基底/ErrorCode/ErrorUtil）
- `main_app` → `util_module`（MyType/RoleUtil/ZeroPadding/IdBridge/ReplaceNull）
- `main_app` → `spring_fragment_module`（/psfm 共通 CSS/JS）
- `spring_login_module`：自モジュール内部で完結、外部へは **Service API のみ公開**

> **禁止**：他モジュールの Entity/Repository 直参照（必ず **Service 越し**）

## 3. グローバル規約（実装ルール）

* インデント：**全コード タブ**
* 文字列：**クラス内は必ず `private final String` 定数化**（Enumで崩れる箇所も文字列定数）
* 条件文：**`MyType`** のメソッドを基本使用。否定は **private の `isNotXxx()`** を用意（`!=` 直書き禁止）
* 変数：**基本 `final`**
* 例外：各コンポーネントで `XxxException extends MyRuntimeException` + `XxxErrorCode implements ErrorCode`
* エラーハンドリング：**ControllerAdvice + ErrorUtil** で統一（`errorCode` / `errorMessage` をフラッシュ）
* フロント：入力便益チェックは `/psfm/js/common/utils.js`、サーバは Validator + Service で最終防御

## 5. メッセージ運用（ValidationMessageUtil）

## 8. Service 公開API 詳細（引数 / 戻り / 副作用 / 例外）

> 原則：**Controller は薄く**、ユースケース・取引境界（`@Transactional`）・**メソッド認可**（`@PreAuthorize`）は **Service** に集約。

### 8.1 users

#### 8.1.1 `register(USER_UsersInputDto input)`

* 権限：`hasRole('ADMIN')`（管理UI） or 公開登録ユースケース
* 引数：`username`（必須）, `rawPassword`（必須）, `email`（任意/方針）
* 戻り：`String`（生成ID `US########`） or `USER_UsersViewDto`
* 副作用：作成・パスワードエンコード・既定権限付与（方針）
* 例外：`UsersErrorCode.DUPLICATE`, `UsersErrorCode.INVALID_INPUT`, `UsersErrorCode.INTERNAL_ERROR`

#### 8.1.2 `updateProfile(USER_UsersInputDto input)`

* 権限：`hasRole('USER')`
* 戻り：`void`
* 副作用：プロフィール更新
* 例外：`UsersErrorCode.NOT_FOUND`, `UsersErrorCode.FORBIDDEN`, `UsersErrorCode.INVALID_INPUT`

#### 8.1.3 `changePassword(PasswordChangeInputDto input)`

* 権限：`hasRole('USER')`
* 引数：`userId`, `oldPassword`, `newPassword`
* 戻り：`void`
* 副作用：パスワード更新（エンコード）
* 例外：`UsersErrorCode.INVALID_STATE`, `UsersErrorCode.NOT_FOUND`

### 8.2 authority

#### 8.2.1 `assignToUser(String userId, String authorityName)`

* 権限：`hasRole('ADMIN')`
* 戻り：`void`
* 副作用：権限付与（DB格納時は `RoleUtil` で `ROLE_`）
* 例外：`AuthorityErrorCode.INVALID_INPUT`, `AuthorityErrorCode.NOT_FOUND`

#### 8.2.2 `revokeFromUser(String userId, String authorityName)`

* 権限：`hasRole('ADMIN')`
* 戻り：`void`
* 副作用：権限剥奪
* 例外：`AuthorityErrorCode.INVALID_INPUT`, `AuthorityErrorCode.NOT_FOUND`

### 8.3 kurohon_questions

#### 8.3.1 `create(QuestionsInputDto input)`

* 権限：`hasRole('ADMIN')`
* 主要引数：`chapterId`, `questionNo`, `optionCount(2..5)`, `answerCountMax(1..optionCount)`, `correctOption(A..E)`, `explanationHtml`
* 戻り：`String`（`KQ########`） or `KurohonQuestionsViewDto`
* 副作用：一意制約（`chapter_id + question_no`）検査・保存
* 例外：`QuestionsErrorCode.INVALID_INPUT`, `QuestionsErrorCode.DUPLICATE`, `QuestionsErrorCode.NOT_FOUND`

#### 8.3.2 `update(QuestionsInputDto input)`

* 権限：`hasRole('ADMIN')`
* 戻り：`void`
* 例外：`QuestionsErrorCode.NOT_FOUND`, `QuestionsErrorCode.INVALID_INPUT`

#### 8.3.3 `findByChapter(String chapterId)`

* 権限：`hasRole('USER')`
* 戻り：`List<KurohonQuestionsViewDto>`
* 例外：`QuestionsErrorCode.NOT_FOUND`（方針により空返却可）

#### 8.3.4 `findRandom(Scope scope)`

* 権限：`hasRole('USER')`
* 引数：`chapterId` or `bookId`
* 戻り：`KurohonQuestionsViewDto` or `Optional<>`
* 例外：`QuestionsErrorCode.NOT_FOUND`

### 8.4 answer_records

#### 8.4.1 `save(USER_AnswerRecordsInputDto input)`

* 権限：`hasRole('USER')`
* 主要引数：`questionId`, `answers[]`, `elapsedMillis`
* 正規化：**「わからない」単独**／「わからない」除く選択数 ≤ `answerCountMax`
* 戻り：`String`（`AR########`） or `void`
* 副作用：履歴登録 → **weakness** 最小同期更新
* 例外：`AnswerRecordsErrorCode.INVALID_INPUT`, `AnswerRecordsErrorCode.NOT_FOUND`

#### 8.4.2 `listByUser(String userId, DateRange range)`

* 権限：`hasRole('USER')`
* 戻り：`USER_AnswerRecordsViewDtoList`
* 例外：`AnswerRecordsErrorCode.NOT_FOUND`（基本は空返却）

#### 8.4.3 `statsForUser(String userId)`

* 権限：`hasRole('USER')`
* 戻り：`AnswerStatsViewDto`
* 例外：なし（空集合許容）

### 8.5 weakness

#### 8.5.1 `bumpFromAnswer(AnswerEvent event)`

* 権限：`hasRole('USER')`
* 戻り：`void`
* 副作用：苦手指標をインクリメンタル更新（直近/累積）
* 例外：`WeaknessErrorCode.INVALID_INPUT`

#### 8.5.2 `topWeakChapters(String userId, int limit)`

* 権限：`hasRole('USER')`
* 戻り：`List<WeakChapterViewDto>`
* 例外：なし（空集合許容）

#### 8.5.3 `resetScope(String userId, WeakScope scope)`

* 権限：`hasRole('USER')`
* 戻り：`void`
* 副作用：分析範囲の再計算/クリア
* 例外：`WeaknessErrorCode.INVALID_INPUT`

> **補足（DTO/引数の初出）**
> `DateRange`：期間値オブジェクト（from/to）。
> `Scope`/`WeakScope`：範囲指定。**不正組合せは INVALID_INPUT**。
> `AnswerEvent`：解答結果イベント。**集約越境更新は Service API 経由のみ**。

### 9.2 Service（認可＋取引境界＋最終整合）

```java
@org.springframework.stereotype.Service
public class USER_AnswerRecordsService {

	private final String WORD_UNKNOWN = "UNKNOWN";

	@org.springframework.security.access.prepost.PreAuthorize("hasRole('USER')")
	@org.springframework.transaction.annotation.Transactional
	public String save(final USER_AnswerRecordsInputDto input) {
		final String qid = type.MyType.orEmpty(input.getQuestionId());
		if (type.MyType.isBlank(qid)) {
			throw new USER_AnswerRecordsException(AnswerRecordsErrorCode.INVALID_INPUT);
		}
		// 「わからない」単独化、上限確認、擬似ID→実ID、保存、弱点の最小更新
		return qid; // ダミー
	}
}
```

## 10. セキュリティ基本則（URL/メソッドの二重防御）

* UI 分岐（hasRole）＋ Service メソッド認可（`@PreAuthorize("hasRole('...')")`）の**二重防御**
* 認可を跨ぐ更新は **対象モジュールの Service API のみ** から実行
* 例外メッセージはユーザ表現に落とし、内部構造やスタックは出さない
* ロール表現の正規化は **RoleUtil** 経由に統一

## 11. DB / ID / シード方針（概要）

* 主キー：接頭辞＋ゼロ埋め ID 文字列（**ZeroPadding**）
* 外部キー：ID（文字列）参照で統一
* NOT NULL：ID/作成日時/更新日時/論理削除フラグ 等
* 論理ユニーク：例 `chapter_id + question_no`
* 擬似/実ID：**IdBridge** で相互変換（I/O 層でブレさせない）
* シード：`sql/schema/*.sql` → `sql/data/*.sql`。大量挿入はファイル分割可

## 13. 運用（更新の流れ）

1. **新画面追加**

   * `AppPath`/`TempPath` に定数追加 → Controller は **定数のみ参照**
   * Form/Validator/Service を作成・連携
   * 本章 **7** の **チェックリスト表** を追記
2. **API 追加/変更**

   * 本章 **8** に **API詳細**（引数/戻り/副作用/例外）を追記
   * 例外コードは **`XxxErrorCode` に定義**し `messages.properties` に文言追加
3. **ユーティリティ/規則**

   * Null/空/比較 → `MyType` / `ReplaceNull`
   * ロール表現 → `RoleUtil`
   * ID 桁/変換 → `ZeroPadding` / `IdBridge`

### 16.2 遷移フロー（要約）

* **ログイン →（初回）パスワード設定 → 権限で分岐（ADMIN は設定、USER はホーム）**
* **ホーム → ⿊本問題集 → 参考書選択 → 章選択 → 問題選択 → 解答 → 答え合わせ → 解説**
* **解答分析** は書籍コンテキストから遷移。戻りはパン屑/ナビで制御。 

### 16.3 画面ごとの機能/イベント（抜粋）

* **ログイン画面**：必須チェック、ログイン処理、ロール判定、遷移制御（ボタン押下） 
* **初回ログイン（パス設定）**：必須/強度/一致チェック、設定後の遷移制御（ボタン押下） 
* **参考書/章/問題**：データ存在チェック、URL 生成（リンク/ボタン押下）、ランダム出題（全体/章） 
* **解答**：必須/指定数選択チェック、未保存警告、解答終了時の保存→結果へ遷移（モーダル/ボタン押下） 
* **答え合わせ/解説/分析**：結果一覧/解説リンク/弱点表示（遷移元は結果画面）、戻りはナビ/パン屑で制御

## 19. 実装ヒント（ID/権限/Null/桁揃え）

* **ID 命名**は「コンポーネント固定 2 文字 + 連番/派生」で表現（例：`US0000`, `KQ000001`）。入出力では **IdBridge** で擬似/実 ID を相互変換。桁は **ZeroPadding**。 
* **権限**は表示名↔DB 名（`ROLE_` 付与/除去）を **RoleUtil** で統一。
* **Null/空の正規化**は **ReplaceNull** / **MyType** 方針に従う。
* **フロント**では utils.js の `defaultIfBlank`, `firstNonBlank` などを活用。
