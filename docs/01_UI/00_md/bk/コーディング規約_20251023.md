# コーディング規約.md
（Java資格勉強_黒本学習システシステム開発 / 2025-10-23）

## 1. 総則

### 1.1 目的  
安全で保守しやすいシステムを実現するため、言語ごとの書式と記述ルールを統一する。  
目的は以下の3点：  
- 読みやすく、追えるコードを残すこと  
- DB・サーバ・ブラウザ間の責務を明確にすること  
- 意図の分かるコメントで自走可能にすること  

### 1.2 適用範囲  
全モジュール（Java / JS / CSS / HTML / SQL / properties / Test）に適用。  
**インデントは全言語タブ統一**とする（例外はYAMLのみ2スペース）。

## 2. Java実装規約

### 2.1 構造・行数・ネスト

| 項目 | 規定値 | 備考 |
|------|--------|------|
| 1行最大文字数 | 100文字 | 改行優先（引数は1引数/行で折返し） |
| ファイル行数 | 1,000行目安 | 超過時は分割を検討 |
| メソッド行数 | 80行上限（40目安） | 小分割・早期return |
| ネスト深さ | 2段まで | 3段目はガード節で脱出 |
| 循環的複雑度 | 10以下 | 超過時はメソッド分割 |

---

### 2.2 記法／命名ルール

| 要素 | 規約 |
|------|------|
| インデント | タブ固定（4幅） |
| 条件判定 | `MyType` を使用。否定は `isNotXxx()` |
| 定数 | `private static final String` 形式。マジック値禁止（0/1/-1/""/emptyのみ例外） |
| DTO | `record`（Java21）で定義。Formのみ可変 |
| コメント | 「なぜそう書くか」を記述（手順説明は不要） |
| Javadoc | public/protected メソッド必須（`@param` / `@return` / `@throws`） |
| アクセス修飾子順序 | public → protected → package-private → private → abstract → static → final |
| @Override | 必須 |
| static利用 | **純関数のみ許可**。状態保持は禁止 |
| Serializable | 必要時のみ。`serialVersionUID` を明示 |
| import | ワイルドカード禁止（明示import） |

### 2.3 EntityとDBデフォルト値（A方針）

```java
@Entity
@DynamicInsert // null列をINSERT文に含めない
@Table(name = "users")
final class UsersEntity {
	@Id
	@Column(name = "id")
	private String id;

	@Column(
		name = "created_at",
		insertable = false,
		updatable = false,
		columnDefinition = "timestamp with time zone default now()"
	)
	@Generated(GenerationTime.INSERT)
	private OffsetDateTime createdAt;
}
```

| 目的 | 設定 | 補足 |
|------|------|------|
| DBデフォルト尊重 | `@DynamicInsert` | Hibernate専用だが採用可 |
| DBが埋める列 | `insertable=false, updatable=false` | |
| DB値即反映 | `@Generated(GenerationTime.INSERT)` または `save→refresh()` | |
| 更新日時等 | `@PreUpdate` または DBトリガー | |

### 2.4 Repository方針（実装クラス排除）

- Repositoryは **インターフェースのみ**。Implを作らない。  
- CRUDはJpaRepository、条件検索はJpaSpecificationExecutor。  
- 付加処理はdefaultメソッド内で実装可。  

```java
public interface AttemptSessionRepository
		extends JpaRepository<AttemptSessionEntity, String>,
		        JpaSpecificationExecutor<AttemptSessionEntity> {

	Optional<AttemptSessionEntity> findTopByUserIdOrderByCreatedAtDesc(String userId);

	default AttemptSessionEntity saveAndReload(AttemptSessionEntity e, EntityManager em) {
		AttemptSessionEntity saved = save(e);
		em.refresh(saved);
		return saved;
	}
}
```

---

### 2.5 Specification共通例
```java
public final class AttemptSessionSpecs {
	private AttemptSessionSpecs() {}
	public static Specification<AttemptSessionEntity> userIdEquals(String userId) {
		return (root, q, cb) -> cb.equal(root.get("userId"), userId);
	}
}
```

### 2.6 例外・エラーコード
- 例外は `MyRuntimeException` 派生クラスで統一。  
- エラーコードは `ErrorCode` 実装enumで管理。  
- 画面出力は `userCode`（問い合わせ番号）までに限定。内部構造は出さない。

## 3. フロントエンド規約

### 3.1 HTML/Thymeleaf
- `<meta charset="UTF-8">` 必須。  
- 出力は `th:text`（エスケープ）を原則。`th:utext`は禁止。  
- セクション区切りコメントを明示：  
	```html
	<!-- [header] START -->
	<!-- [header] END -->
	```

### 3.2 JavaScript
| 項目 | 内容 |
|------|------|
| インデント | タブ固定（4幅） |
| コメント | JSDoc準拠（目的 / 引数 / 戻り値） |
| DOM契約 | 必須class・data属性を冒頭に明記 |
| ファイル命名 | キャメル／ケバブ（例：`setAlertDanger.js`） |
| XSS防止 | `textContent` / `innerText`使用。`innerHTML`禁止。 |
| 共通処理 | `/psfm/js/fragment/` 配下に集約。 |

### 3.3 CSS
- UTF-8。  
- インデント：タブ。  
- カラー／サイズはCSS変数で統一管理。  
- ユーティリティは `my-` プレフィックス採用。

## 10. JUnit実装規約

### 10.1 レイヤ構成
| レイヤ | 内容 |
|--------|------|
| **Unit（最優先）** | Spring起動なし。純ロジック／文字列系／PropKey⇔properties／正規表現の構文・挙動テスト。 |
| **Slice** | `@WebMvcTest` / `@DataJpaTest` など層を限定してSpring起動。MVCのみ・JPAのみ。 |
| **Integration** | `@SpringBootTest`。アプリ起動が必要な経路のみ対象。件数は最小限。 |

### 10.2 配置・パッケージ方針
- **基本**：本体クラスと同一パッケージ階層にミラー配置（`package-private` に触れる・見通しが良い）。
- **@SpringBootTest**：アプリのルート（例：`com.javastudy`）配下に置く。  
  もしくは `@SpringBootTest(classes = <エントリクラス>)` を明示。

### 10.3 命名・書き方
| 項目 | 規約 |
|------|------|
| クラス名 | `XxxTest`（対象クラス名にTestを付与） |
| メソッド名 | 挙動が分かる日本語でOK（例：`username_OK()`、`username_NG_空文字()`） |
| テスト単位 | 1テスト＝1責務（存在／構文／挙動などに分割） |
| コメント | `// arrange`、`// act`、`// assert` で区切る（任意） |
| 失敗メッセージ | 修正指示になる文面で書く（例：「期待値と異なる：〜を修正せよ」） |
| import | 明示指定（ワイルドカード禁止） |
| 定数 | `private static final String`（既存規約に準ずる） |
| コーディング規約 | タブインデント／100桁目安／1メソッド80行上限 |

### 10.4 タグ運用（任意推奨）
| タグ | 用途 |
|------|------|
| `@Tag("contract")` | PropKey／regex／DB構造など契約系テスト |
| `@Tag("integration")` | 統合・結合テスト |
| 実行例 | `mvn -q -Djunit.jupiter.tags.include=contract test` |

### 10.5 テスト資源の扱い
- 配置：`src/test/resources`（推奨）または `src/main/resources` のクラスパス直下。  
- 階層化した場合：`classpath*:**/<name>.properties` で探索可。  
- 文字コード：UTF-8 明示（`InputStreamReader(..., UTF_8)`）。

### 10.6 DB契約テスト
- 目的：`*DB.TABLE` / 内部 `*Column` と **実DB（public）** の存在突合。  
- 起動：`@SpringBootTest` + `DataSource`。テーブル不存在／カラム不足を列挙して失敗。  
- 主キー確認追加時：`DatabaseMetaData#getPrimaryKeys` を使用（任意）。

### 10.7 データと再現性
| 対象 | 方針 |
|------|------|
| Unit | 外部依存ゼロ。`Clock` / `Random` は注入 or 固定値で再現性確保。 |
| Slice/Integration | `application-test.properties` を用意。`spring.jpa.open-in-view=false` を原則。 |
| SQL準備 | `@Sql` 等で再現性を担保。 |

### 10.8 Mockito / JDK21 対応
```xml
<build>
	<plugins>
		<plugin>
			<groupId>org.apache.maven.plugins</groupId>
			<artifactId>maven-surefire-plugin</artifactId>
			<configuration>
				<argLine>-XX:+EnableDynamicAgentLoading</argLine>
			</configuration>
		</plugin>
	</plugins>
</build>
```
依存追加：`mockito-junit-jupiter` / `mockito-inline`

### 10.9 CI / ブランチ運用
- mainへのマージは**全緑**。  
- 未整備で赤を許す場合は、一時ホワイトリスト（システムプロパティ）で明示除外 → 後で削除。  
- 契約系のみの監視をしたい場合は `contract` タグのみ実行をCIに組み込む。

### 10.10 ログテスト（任意）
ログ内容検証が必要な場合のみ `ListAppender` を使用して `traceId` などをアサート（頻用はしない）。

### 10.11 推奨テンプレート

#### 契約テスト雛形

### 補足と実務ポイント

* Code Templatesでは `${cursor}` が使えないため、区切りコメントで代替。
* 保存時整形 & EditorConfig は必須。
* Eclipse → Java > Editor > Save Actions

  * Format source code（ON）
  * Organize imports（ON）
  * Add missing @Override（ON）
* EditorConfig プラグインを有効化し、`.editorconfig` の設定（indent_style=tab, indent_size=4, max_line_length=100）を尊重。

#### 既存ファイルへの反映手順

1. メソッドJavadoc付与: `/**` → Enter でテンプレ展開
2. `<name>` を引数名に置換して埋める
3. Missing Javadoc を Warning 設定 → Ctrl+1 Quick Fix
4. ヘッダ挿入: `^(package[^\n]+;)$` 検索置換
5. Getter/Setter/Constructor 再生成
6. Save Actions実行（Format/Imports/Override）
